Проверка качества временного ряда
Задача
Проверить структуру и качество многомерного временного ряда, не изменяя
исходные наблюдения. Прочитайте input.json и запишите output.json
в ту же папку.

Вход
{
  "dataset": {
    "timestamps": [
      "2016-01-01T02:00:00",
      "2016-01-01T05:00:00",
      "2016-01-01T05:00:00",
      "2016-01-01T08:00:00",
      "2016-01-01T06:00:00",
      "2016-01-01T11:00:00"
    ],
    "values": {
      "temperature_c": [1.0, null, 2.0, 3.0, 4.0, 5.0],
      "wind_speed_ms": [0.0, 1.0, 1.0, null, 0.0, 1.0]
    }
  },
  "method": "check",
  "parameters": {}
}
timestamps — строки строго вида YYYY-MM-DDTHH:MM:SS (местное
время, без Z, без долей секунды и без смещения). Любая другая
форма — ошибка структуры.
values — именованные числовые ряды. Каждый массив той же длины,
что timestamps. null означает пропуск.
Выход
{
  "missing_values": {"temperature_c": [1], "wind_speed_ms": [3]},
  "duplicate_timestamp_indices": [2],
  "timestamps_out_of_order_indices": [4]
}
Правила:

ответ содержит ровно три поля;
индексы с нуля, в каждом списке — по возрастанию;
missing_values — все индексы null; переменная без null не
включается; если пропусков нет — {};
duplicate_timestamp_indices — второе и последующие вхождения метки;
метки сравниваются как строки; если дублей нет — [];
timestamps_out_of_order_indices — метка меньше непосредственно
предыдущей; равные метки нарушением порядка не считаются; если
нарушений нет — [];
списки независимы: один индекс может попасть в оба;
пустые timestamps и values допустимы, ответ — {}, [], [];
проверяются только эти три вида проблем. Отсутствие метки в сетке,
выбросы и константные ряды не проверяются.
Ошибки структуры
Если файл не читается, нет dataset/timestamps/values, длины не
совпадают, метка не вида YYYY-MM-DDTHH:MM:SS или значение не число и
не null, верните ровно
{"status":"error","message":"format data error"}.

Поля method и parameters на проверку не влияют; лишние поля во
входе игнорируются.
